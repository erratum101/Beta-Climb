# Сверка советов с Ego-Exo4D

`compare_egoexo.py` готовит локальную форму для тренера, который сравнивает советы Beta Climb с экспертными комментариями на той же попытке. Для запуска нужны Python 3 и два уже сохранённых JSON-файла. Скрипт работает отдельно от воркера, без сети и дополнительных библиотек.

## Подготовка

Выберите одну запись `Rock Climbing` в **demonstration annotations**. В этой разметке `good_executions` содержит позитивные наблюдения, а `tips_for_improvement` — замечания и советы. У каждой отметки есть время в секундах, реплики эксперта, его идентификатор и имя видео. [Описание формата Ego-Exo4D](https://docs.ego-exo4d-data.org/annotations/proficiency_estimation/)

Заранее зафиксируйте `take_uid`, ракурс, начало и длительность непрерывного фрагмента до 60 секунд. Используйте синхронизированный ракурс исходной записи, сохраните результат анализа именно этого фрагмента из `GET /api/attempts/{id}?profileId=…`. Статус должен быть `ready` или `limited`, в том числе когда карточек нет. Передайте в продукт только видео и обычные параметры профиля. Экспертные комментарии открывайте для сверки после фиксации ответа.

Из папки `backend/worker/evaluation` выполните команду, подставив локальные пути и параметры своего фрагмента.

```sh
python3 compare_egoexo.py \
  --annotations /path/to/demonstrations.json --take "$TAKE_UID" \
  --view exo1 --start 35.5 --duration 20 \
  --attempt /path/to/saved-attempt.json > /path/to/new-review.json
```

Форма содержит SHA-256 обоих входных файлов, идентификатор попытки, ракурс и границы фрагмента. Используйте отдельный выходной файл для каждой рецензии. Одинаковая длительность двух видео ещё не подтверждает, что загружен нужный фрагмент. Это сверяют по источнику, ракурсу и точке обрезки до рецензирования.

## Заполнение формы

1. Просмотрите фрагмент. У каждого экспертного комментария `pauseInTakeSec` задаёт точечную отметку в исходном видео. `pauseRelativeToClipSec` сдвигает её на начало фрагмента. Например, отметка 41,0 с при обрезке с 35,5 с окажется на 5,5 с. По инструкции проекта тренер комментирует уже увиденное и может остановить видео после завершения движения. Поле `pauseInsideClip` относится к полуоткрытому интервалу фрагмента. В форме сохранены и более поздние отметки, поскольку их текст может относиться к видимому движению. [Как записывали комментарии](https://docs.ego-exo4d-data.org/annotations/expert_commentary/)
2. Сверьте реплики каждого эксперта с кадрами в окрестности его отметок. В `expertAnnotations[].review` заполните `visibility` одним из значений `visible`, `outside`, `unclear`. Если наблюдение видно, укажите оценённый по кадрам интервал движения в секундах от начала клипа в `observedClipIntervalSec`. Одну точку допустимо записать как `[t, t]`. У позитивного наблюдения отметьте, что именно эксперт одобрил.
3. Сопоставьте каждую карточку с движением, частью тела и предлагающимся изменением. В `modelAdvice[].review.decision` укажите `agrees`, `partial`, `contradicts`, `no_reference` или `unclear`. В `referenceIds` перечислите только экспертные реплики, на которые опирается решение, и поясните выбор в `notes`. Если эксперт хвалит положение корпуса, а модель советует изменить постановку стопы в ту же секунду, возможен `no_reference`. Если модель предлагает исправить именно то движение, которое эксперт хвалит, проверьте контекст на возможное противоречие.
4. Запишите в `unmatchedVisibleTipIds` видимые замечания экспертов, тему которых модель пропустила. Совет модели без экспертного аналога остаётся в форме с `no_reference`. Отсутствие реплики эксперта само по себе не устанавливает ошибку. Укажите рецензента и установите `reviewComplete` после заполнения обеих сторон, включая попытки без советов.

Форма предназначена для качественной проверки локализации и смысла. Скрипт не присваивает пары или баллы по совпадению таймкодов, не вычисляет precision/recall и не передаёт эталон в модель. Для повторной проверки сохраните входные файлы и обе независимые рецензии локально.

Синтетические тесты проверяют формат аннотаций, сдвиг таймкодов, несовпадение смысла при попадании в один интервал и отсутствие карточек. Выполните `python3 -m unittest discover -p 'test_*.py' -v` из той же папки.
