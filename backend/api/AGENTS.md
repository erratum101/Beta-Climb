# Правила работы с Java API

Эти правила действуют для `backend/api` и всех вложенных каталогов.
Ориентир по форматированию — `src/main/java/ru/betaclimb/services/AttemptService.java`.

## Форматирование Java-кода

- Используй отступ в 4 пробела, без табуляции. Для продолжения выражений и параметров в многострочных объявлениях добавляй ещё 8 пробелов относительно начала объявления.
- Открывающую фигурную скобку ставь на той же строке, что и объявление или условие. `else` и `catch` размещай на строке закрывающей скобки предыдущего блока.
- Разделяй `package`, импорты и объявление класса пустыми строками. Импорты `java.*` отделяй пустой строкой от остальных импортов, как в `AttemptService.java`. Не используй wildcard-импорты.
- В классе сначала размещай константы, затем поля зависимостей, конструкторы и методы. Разделяй эти группы пустой строкой; между методами и конструкторами также оставляй пустую строку.
- Внутри методов обязательно используй логические пустые строки: отделяй получение данных, проверки, подготовку значений, действия с хранилищем или репозиторием и формирование результата, когда это самостоятельные этапы. Связанные объявления и операции оставляй вместе. Не вставляй пустую строку после каждой инструкции и не используй несколько пустых строк подряд.
- Для внедрения зависимостей используй Lombok `@RequiredArgsConstructor` на классе и `private final` поля. Не пиши вручную конструкторы, которые только присваивают параметры полям, даже если зависимость одна. Явный конструктор оставляй, когда нужны дополнительная логика инициализации, преобразование или проверка параметров либо специальные аннотации параметров (например, `@Qualifier`), которые не настроены для переноса Lombok.
- Не используй Spring `@Value` для настроек приложения. Объединяй связанные настройки в типизированные классы `*Properties` с `@ConfigurationProperties`, размещай их в пакете `ru.betaclimb.properties` и регистрируй через `PropertiesConfiguration`. Внедряй эти классы через `private final` поля и `@RequiredArgsConstructor`. Значения по умолчанию, нормализацию и валидацию настроек задавай в properties-классах; имена свойств и привязки к переменным окружения сохраняй в `application.properties`. Инициализацию ресурсов после внедрения зависимостей выполняй в `@PostConstruct`.
- Если нужен явный большой конструктор, оформляй его многострочно: каждый параметр — на отдельной строке, включая первый. Закрывающую круглую скобку размещай на отдельной строке на уровне объявления, затем ` {`. Применяй это правило к конструкторам с тремя и более параметрами, а также когда однострочное объявление становится длинным или плохо читается.
- Объекты с большим конструктором (три и более параметра) создавай через builder, сгенерированный аннотацией Lombok `@Builder` на соответствующем классе или конструкторе. Не передавай длинный список позиционных аргументов через `new`. Каждый вызов настройки поля builder и завершающий `.build()` размещай на отдельной строке. Это правило относится к создаваемым вручную объектам; конструкторы внедрения зависимостей Spring оформляй по правилу выше. Если конструктор принадлежит сторонней библиотеке и builder недоступен, указывай каждый аргумент на отдельной строке.
- Вызовы методов с тремя и более аргументами обязательно оформляй многострочно независимо от длины строки: каждый аргумент, включая первый, — с новой строки; закрывающая скобка — на отдельной строке на уровне начала вызова. Аналогично оформляй длинные объявления методов и вызовы с меньшим числом аргументов, если они плохо читаются в одну строку.
- Длинные цепочки вызовов разбивай по операциям: каждый следующий вызов с точкой — на новой строке с отступом продолжения, как цепочка `stream()` в `AttemptService.java`.
- При изменениях сохраняй стиль окружающего кода и добавляй логическое разделение в редактируемых блоках. Не переформатируй несвязанные участки или весь модуль без отдельной задачи.

Пример внедрения зависимостей через Lombok:

```java
@RestController
@RequestMapping("/api/attempts")
@RequiredArgsConstructor
public class AttemptController {
    private final AttemptService attempts;
}
```

Пример создания объекта через Lombok builder (класс `UploadRequest` должен быть аннотирован `@Builder`):

```java
UploadRequest request = UploadRequest.builder()
        .owner(owner)
        .profileId(profileId)
        .requestId(requestId)
        .build();
```

Пример вызова метода с большим количеством аргументов:

```java
StoredAttempt attempt = attempts.find(
        owner,
        profileId,
        id
);
```

Пример логического разделения внутри метода:

```java
StoredAttempt attempt = requireAttempt(
        owner,
        profileId,
        id
);
String key = attempt.sourceKey();

if (!key.startsWith("betaclimb/" + id + "/")) {
    throw new ResponseStatusException(HttpStatus.NOT_FOUND);
}

return storage.open(key);
```
