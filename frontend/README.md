# Beta Climb

Мобильный интерфейс разбора одной попытки на скалодроме.

Пользователь снимает прохождение и открывает эпизоды разбора по таймкодам. Java API сохраняет профиль и состояние попытки в PostgreSQL, видео — в приватном S3. Python-воркер обрабатывает запись и публикует до трёх замечаний с наблюдениями и источниками. Инструкции для запуска всех компонентов приведены в [корневом README](../README.md).

В [отчёте RatPoC](ratpoc/REPORT.md) сохранены результаты проверки на открытых видео: лимит времени обработки выполнен на тестовом оборудовании, качество контактов пока не достигло выбранных порогов. Код, инструкции запуска, источники данных и результаты находятся в папке `ratpoc/`.

## Запуск

API и фронтенд запускаются локально в Docker, PostgreSQL — managed-база Timeweb.
Из корня репозитория создай `docker/.env.managed` по примеру
`docker/.env.managed.example` и заполни параметры подключения. Этот файл исключён из Git;
пароль указывается как есть, без URL-кодирования и shell-экранирования.
CA-сертификат должен находиться в `~/.cloud-certs/root.crt`:

```bash
mkdir -p ~/.cloud-certs
curl --fail -o ~/.cloud-certs/root.crt https://st.timeweb.com/cloud-static/ca.crt
chmod 0600 ~/.cloud-certs/root.crt
```

Запуск из корня репозитория:

```bash
docker compose --env-file .env -f docker/docker-compose.yml up --build -d
```

Если Compose установлен отдельной командой, используй `docker-compose` вместо
`docker compose`. Для открытия анкеты и приложения используйте [вход в прототип](http://localhost:5174/app?source=home).
Compose запускает `api` и `frontend`. API подключается к `default_db` по TLS
с проверкой сертификата и имени сервера (`verify-full`). Миграции из
`backend/migrations` упаковываются в API и выполняются Flyway при запуске
в схеме `betaclimb`; Spring Data JPA использует ту же схему.
Контейнер `db` с локальным volume оставлен в профиле `local-db` и по умолчанию не запускается.

Для разработки фронтенда отдельно (API должен слушать `localhost:8080`):

```bash
npm ci
npm run dev
```

Приложение откроется на `http://localhost:5173`. В `localStorage` хранится UUID профиля;
сам профиль загружается из PostgreSQL. Доступ к попыткам привязан к HttpOnly-cookie браузера.
«Сбросить локальные данные» забывает UUID в браузере, не удаляя запись из БД.

## Что делает первая версия

1. Профиль: ник, рост, вес, возраст, опыт, типы трасс, максимальная категория, пол, согласие.
2. Условия съёмки: один человек, неподвижная камера, вся секция стены, различимые цвета, чёткий кадр.
3. Выбранный файл загружается через API. История сохраняет статус попытки после обновления страницы.
4. Статус разбора: зацепки и трасса → положение тела и контакты → рекомендации.
5. Отказ, если кадр не подходит. Система не придумывает разбор.
6. Плеер воспроизводит реальную запись и переходит к выбранному эпизоду. Результат может содержать частичные наблюдения и ограничения съёмки.
7. Можно загрузить следующую попытку. Экран сравнения доступен при наличии сопоставленных эпизодов.
8. История по дням и сетка пролазов.

Вне первой версии: замена тренера, идеальная бета, сила и форма, несколько людей в кадре, оценка «техники» одним баллом.

## Слои

```text
src/pages          экраны
src/features       сценарии: профиль, плеер разбора
src/entities       подписи, группировка попыток
src/shared/ui      кнопки, поля, навигация
src/shared/api     контракт ClimbApi
```

Экраны не знают, откуда берутся данные. Они вызывают `useSession()`. Сессия ходит только в `climbApi`.

`climbApi` запрашивает профиль и попытки через HTTP. Для попыток предусмотрены загрузка, просмотр истории и выдача временной ссылки на видео. Операции с профилем перечислены ниже.

- `POST /api/profiles` — создание, ответ `{ id, profile }`.
- `GET /api/profiles/:id` — чтение.
- `PUT /api/profiles/:id` — обновление.

Java-слои: `controllers → services → repositories` (Spring Data JPA).
Тело POST/PUT соответствует `AthleteProfile` из `src/shared/api/types.ts`.
Ошибки валидации возвращают HTTP 400, неизвестный UUID — 404.

Тесты API и миграции: `cd backend/api && ./gradlew test` из корня репозитория;
нужен работающий Docker. Для Colima перед запуском задай:

```bash
export DOCKER_HOST="unix://$HOME/.colima/default/docker.sock"
export TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock
```

## Метрики, под которые собирается продукт

North Star — завершённый цикл: попытка → применимая рекомендация → повтор → наблюдаемое изменение целевого движения.

| Метрика | Что считается |
| --- | --- |
| Hold detection mAP / recall | Насколько верно найдены зацепки |
| Contact F1 | Верно ли найден контакт левой/правой руки и ноги |
| Route identification accuracy | Доля видео с правильно определённой трассой |
| Movement sequence accuracy | Совпадение последовательности движений с разметкой |
| Expert agreement | Доля рекомендаций, которые эксперт считает применимыми |
| Analysis completion | Доля видео, дошедших до результата или честного отказа |
| Second attempt rate | Доля разборов, после которых снята следующая попытка |
| Improvement rate | Доля повторов, где целевое движение изменилось |
