# Beta Climb RatPoC

Микропрототип проверяет одно допущение: из видео скалолазной попытки до 60 секунд можно автоматически получить 2D-траектории тела и интервалы предполагаемого использования зацепок за **не более 300 секунд** на зафиксированном оборудовании. Цель — 180 секунд.

## Риски

| Риск | Вероятность | Влияние | Работа с риском |
| --- | --- | --- | --- |
| R1: ошибки позы, масок и сопоставления конечностей с зацепками | Высокая | Критическое | Основной риск PoC: измерить качество и ограничить условия съёмки |
| R2: обработка дольше 5 минут | Средняя | Высокое | Замерить весь локальный конвейер |
| R3: рекомендации по данным не помогают спортсмену | Высокая | Критическое | Отдельный будущий эксперимент с экспертом |

## Короткий план

1. Взять три открытые записи: одну для разработки, две для контрольной проверки; хотя бы один контрольный фрагмент — 60 секунд.
2. Готовой моделью выделить зацепки на нескольких кадрах неподвижной стены, готовой моделью позы получить ключевые точки тела при 10 кадрах/с.
3. По расстоянию до масок и устойчивости во времени оценить контакты кистей и стоп. Потери наблюдения сохранять как `unknown`.
4. Сохранить JSON, диагностическое видео и время каждого этапа. Сопоставить события с независимой разметкой.
5. Проверить precision ≥ 85%, recall ≥ 80% при совпадении конечности, зацепки и temporal IoU ≥ 0.5; оценивать каждое контрольное видео, руки и ноги отдельно. Время каждого контрольного запуска ≤ 300 секунд.

Условия: один спортсмен, неподвижная камера, видимая стена и тело. Желательны начальные кадры стены без спортсмена. Отклонения открытых записей от этих условий фиксируются в отчёте.

Событие означает **предполагаемое использование**, а не измеренный захват или перенос веса. `no_hold` означает отсутствие найденного контакта с зацепкой; опора на стену этим не исключается. Автоматический конвейер не получает эталонные координаты зацепок. Прогон с эталонной картой допустим только как отдельно обозначенная диагностика.

Время включает чтение видео, загрузку локальных весов, распознавание, сопоставление и запись JSON. Скачивание ресурсов, сетевую загрузку пользователем и очередь не измеряем. Визуализацию измеряем отдельно. Маленькая выборка подтверждает только работоспособность в проверенных условиях.

Вне эксперимента: обучение моделей, определение трассы, рекомендации, API, интерфейс, аккаунты и БД.

## Проверенный результат

Прогоны и выводы — в [REPORT.md](REPORT.md). На Apple M4 Pro обработка заняла **29–46 секунд**, но качество контактов не достигло порогов. Технический риск R1 остаётся открытым. В `results/` опубликованы JSON и изображения диагностики; видео с наложением создаются локально.

Повторная проверка тех же трёх записей с фиксированными критериями, контролем SHA-256 и покадровой оценкой описана в [VERIFICATION.md](VERIFICATION.md). В наборе нет независимых координат суставов: наличие траекторий не подтверждает их точность.

[Проверка допусков времени и перекрытий](TOLERANCE.md) разделяет восстановление длительности контакта и обнаружение самого факта. Даже при учёте только видимых уникальных пар, без проверки времени и повторов, precision на контролях составляет 60.0% и 58.3%.

## Запуск

Проверено на macOS ARM64, Python 3.12, FFmpeg в PATH. Все команды выполняются из этой папки. Нужны `uv` и FFmpeg.

```sh
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python fetch_assets.py
sh run_demo.sh
```

`fetch_assets.py` скачивает три выбранные записи из большого ZIP через HTTP Range: весь 20-гигабайтный архив не скачивается. Веса и видео сохраняются локально; исходные источники и контрольные суммы — в [sources.json](sources.json), атрибуция — в [SOURCES.md](SOURCES.md). Точный набор установленных пакетов первоначального запуска — `requirements-lock.txt`.

Видео, веса моделей, виртуальное окружение и кэши исключены из Git. Эталонная разметка, результаты и диагностические изображения включены. Пути к ресурсам в опубликованных `result.json` относительны к папке `ratpoc`: после скачивания ресурсов можно повторно вызвать `render.py` из этой папки.

Один файл можно обработать отдельно:

```sh
.venv/bin/python prototype.py assets/clips/p4_green.mp4 --output results/my-run
.venv/bin/python evaluate.py results/my-run/result.json --annotations assets/annotations/p4_green
.venv/bin/python render.py results/my-run/result.json
.venv/bin/python -m unittest test_metrics.py
```

Повторить формальную проверку в новую папку: `.venv/bin/python verify_poc.py --output results/my-verification`. Все тесты: `.venv/bin/python -m unittest discover -p 'test_*.py'`.

Для своего видео достаточно первой и третьей команд с нужным путём; `evaluate.py` предназначен для разметки The Way Up. Вход — не длиннее 60 секунд. Исходный размер кадра сохраняется, точки и маски используют одну систему координат. Запуск по умолчанию использует CPU.

На macOS MediaPipe инициализирует системный OpenGL-контекст даже с CPU delegate. В ограниченной песочнице возможна ошибка `Could not create an NSOpenGLPixelFormat`; запуск из обычного локального терминала решает именно это ограничение окружения.

## Файлы результата

- `result.json`: карта зацепок, 33 точки `[x, y, visibility, presence]` на каждом обработанном кадре, наблюдения четырёх конечностей и интервалы предполагаемых контактов. Низкая уверенность остаётся в данных, потеря позы — пустой список точек.
- `metrics.json`: время, число обработанных кадров, доля неопределённых наблюдений, оборудование и версии библиотек.
- `evaluation.json`: precision/recall, совпавшие события, пропуски, соответствие автоматически найденных зацепок эталонным.
- `preview.mp4`, `preview.jpg`: скелет и маски, цветные кандидаты контактов, подписи `unknown` и `no_hold`. Кандидат на отдельном кадре ещё не равен итоговому событию.

`prototype.py` запускает модели, `evaluate.py` только оценивает сохранённый результат, `render.py` только визуализирует его. Подробные метрики не зависят от рендеринга. Итоговые события требуют не менее 0.5 секунды наблюдаемой близости; допускается разрыв до 0.2 секунды, при этом исходные неизвестные кадры сохраняются.
