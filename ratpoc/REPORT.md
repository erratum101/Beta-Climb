# Результаты микропрототипа Beta Climb

Проверка выполнена 15 октября 2026 года. **Лимит вычислений 300 секунд выполнен на выбранном компьютере. Требования к качеству контактов не выполнены.** Реализуемость преобразования видео в достаточно достоверные данные выбранной связкой моделей пока не подтверждена.

## Что запущено

Готовый YOLO26n для зацепок → MobileSAM для их масок → MediaPipe Pose Landmarker Heavy → расстояние кистей и стоп до масок → устойчивые во времени события. Обучения моделей и ручной разметки на входе автоматических прогонов нет.

Карта строится по кадрам 0, 0.5 и 1.0 секунды, повторные обнаружения объединяются NMS. Тело анализируется при 10 кадрах/с. Порог уверенности зацепок — 0.25; visibility/presence точек — 0.5. Радиус близости зависит от размера корпуса. Минимальная наблюдаемая длительность контакта — 0.5 секунды; допустимый разрыв — 0.2 секунды. Настройки не менялись между разработкой и контрольными прогонами.

Оборудование: **Apple M4 Pro, 14 ядер, 48 GiB RAM, CPU** для всех нейросетей. macOS 26.5 ARM64, Python 3.12.14. Версии моделей, пакетов и входные параметры сохранены рядом с результатами. Для каждого видео приведён один успешный автоматический запуск отдельного процесса с загрузкой локальных весов; системный файловый кэш не очищался. Это не оценка p95 или работы под нагрузкой.

Порог успеха: precision ≥ 85%, recall ≥ 80%, обработка ≤ 300 секунд на каждом контрольном видео. Проверяется также качество рук и ног отдельно.

| Контроль | Руки precision / recall | Ноги precision / recall | Зацепки, использованные в эталоне и найденные в карте |
| --- | --- | --- | --- |
| p3 orange | 20.0% / 5.6% | 27.3% / 35.3% | 91.3% |
| p4 green | 11.1% / 5.3% | 29.6% / 61.5% | 93.3% |

Модели выдавали скелет на всех 387 и 600 обработанных кадрах контрольных видео, но это не означает правильность каждой конечности. Доля `unknown` для левой/правой руки: **92.8% / 84.5%** на p3 и **76.2% / 80.8%** на p4. В автоматическом результате видны пропуски, ложные привязки к соседним зацепкам и дробление контактов.

На минутном фрагменте карта зацепок заняла 5.78 секунды, поза и сопоставление — 37.41 секунды. Остальное время — импорт, подготовка и запись результата. Скачивание, подготовка минутного фрагмента, пользовательская загрузка и серверная очередь сюда не входят. Рендеринг измеряется отдельно в `render_metrics.json`.

## Диагностика с эталонной картой

На записи p2a выполнен дополнительный запуск с заранее известными прямоугольниками зацепок из датасета: precision **62.5%**, recall **50.0%**. Для ног — 72.7% / 84.2%, для рук — 40.0% / 19.0%. Даже такой результат не проходит выбранный порог.

Это оптимистичная диагностика, **не автоматический PoC**: она одновременно убирает посторонние зацепки, задаёт правильные ID и заменяет маски прямоугольниками. Поэтому разницу нельзя целиком приписывать ошибкам сегментации. Низкая полнота контактов рук сохраняется и при такой подстановке.

## Как рассчитано качество

Эталон — опубликованные авторами The Way Up интервалы использования зацепок. Оценивание выполняется отдельным скриптом после инференса:

1. Автоматические ID сопоставляются с эталонными по пересечению прямоугольников, box IoU ≥ 0.3, взаимно однозначно.
2. Событие считается правильным при совпадении конечности, зацепки и temporal IoU ≥ 0.5. Каждому эталонному событию может соответствовать только одно предсказание: дубликаты становятся FP.
3. Не найденные и перекрытые контакты с числовым ID остаются в FN. Отказ от ответа не улучшает recall. Короткие эталонные контакты также остаются в оценке, хотя фильтр длительности может их пропускать.
4. Конечный кадр CSV трактуется как включённый; интервалы обрезаются по длительности клипа. Опора на стену (`w`) и безымянная неправильная зацепка не имеют проверяемого ID и исключаются из эталонных событий. Предсказания на несопоставленных зацепках всё равно считаются FP.

В разметке зацепок есть прямоугольники, но нет пиксельных масок: качество самих контуров количественно не измерялось. Процент найденных использованных зацепок в таблице — диагностическое сопоставление прямоугольников, а не метрика сегментации.

## Ограничения и решение по рискам

Все три видео сняты на одной стене, на двух трассах. Контроль отделён по участникам; оранжевая трасса встречается и в разработке. Используется подготовленное авторами стабилизированное видео с небольшими остаточными смещениями. Кадра совершенно пустой стены нет, в некоторых кадрах есть люди на фоне. Это ограниченная проверка открытых видео, не проверка новых залов или всех условий съёмки.

- **R1 остаётся открытым:** набор траекторий и событий получить можно, но использовать его как надёжную основу рекомендаций пока нельзя.
- **R2 снижен для этого оборудования:** обработка минутного фрагмента существенно быстрее 180–300 секунд. Перенос на другой сервер и пользовательское ожидание целиком требуют отдельных замеров.
- **R3 не проверялся:** прототип не формирует тренировочные рекомендации.

Следующий небольшой эксперимент: свои видео со штатива, более крупным спортсменом в кадре и видимыми кистями; затем сравнение качества наблюдений рук с другой готовой моделью позы. Оптимизация скорости на этом этапе не является главным ограничением. Неудача данной связки не доказывает невозможность идеи в целом.
