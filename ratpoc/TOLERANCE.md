# Контакты: влияние времени, перекрытий и определения метрики

Проверка от 16 октября 2026 года. Использованы неизменённые предсказания трёх видео из `results/verification`. Модели не запускались повторно и не обучались. Это анализ чувствительности на уже известных данных, а не новая контрольная проверка.

**Итог:** прежние 25–26% precision характеризовали восстановление целого события с достаточным совпадением длительности. Это более строгое требование, чем обнаружить факт использования зацепки. Учёт перекрытий и смягчение метрики улучшают часть результатов, но не дают 70% precision на обоих контрольных видео для всех конечностей. Для рук на отдельных кадрах p4 precision достигает 80.3%, при recall 30.0%.

## Какие условия проверены

1. **Время:** допускается задержка каждого предсказанного события до 0.25 / 0.5 / 1 секунды. Для сопоставления событие можно сдвинуть назад на величину до допуска, с шагом одного исходного кадра (0.04 с). Конечность и зацепка должны совпасть; соответствие событий остаётся взаимно однозначным. Это допуск оценщика, не исправление предсказаний моделью.
2. **Перекрытия:** интервалы `framesOccluded` берутся только из независимой разметки тренера. На них не штрафуются ни предсказания, ни пропуски; полностью скрытые события исключаются из обоих знаменателей. Частично скрытые контакты сравниваются по оставшимся видимым интервалам, без заполнения промежутков. Видимость модели не используется для выбора «удобных» кадров.
3. **Факт контакта:** отдельная мягкая метрика засчитывает совпадение конечности и зацепки при любом положительном пересечении во времени. Она не подтверждает длительность контакта.
4. **Максимально мягкий вариант:** считать уникальные пары «конечность–зацепка», игнорировать время целиком и объединять повторы. Пары без видимых свидетельств исключаются. Разные ошибочные автоматические ID сохраняются разными ложными находками. Эта метрика не подтверждает последовательность движений.
5. **Покадровая диагностика:** оценить исходные кандидаты контактов в обработанные моменты времени. `unknown` на видимом эталонном контакте остаётся пропуском. Также проверен общий фиксированный сдвиг 0 / 0.25 / 0.5 / 1 секунды; при сдвиге исключены скрытые моменты исходного и сопоставленного времени и выход за границы видео.

Источник видимости — [разметка The Way Up](https://arxiv.org/html/2505.12854v1#S3.S4): перекрытие отмечается, когда конечность закрыта более чем наполовину. Эти интервалы размечены во время контактов; полной покадровой разметки видимости вне контакта нет.

## Результаты контрольных видео

В ячейках **precision / recall**: доля верных находок / доля обнаруженных эталонных контактов. Между строками меняется единица оценки, поэтому их нельзя выдавать за одну и ту же «точность».

| Что оцениваем | p3 orange | p4 green |
| --- | --- | --- |
| Исходные события, temporal IoU ≥0.5 | 25.9% / 20.0% | 25.0% / 28.1% |
| Те же события, допускаем задержку до 1 с | 25.9% / 20.0% | 25.0% / 28.1% |
| Только видимая часть событий, temporal IoU ≥0.5 | 29.6% / 25.0% | 30.6% / 35.5% |
| Видимая часть событий + задержка до 1 с | 29.6% / 25.0% | 30.6% / 35.5% |
| Факт видимого контакта: любое пересечение во времени | 55.6% / 46.9% | 41.7% / 48.4% |
| Уникальные видимые пары, без проверки времени и повторов | **60.0% / 46.9%** | **58.3% / 48.3%** |
| Контакт в отдельный видимый момент, все конечности | 48.7% / 34.7% | 67.6% / 46.1% |
| Контакт в отдельный видимый момент, только руки | 36.9% / 14.2% | **80.3% / 30.0%** |

При исключении перекрытий полностью исчезли 3 из 35 эталонных событий p3 и 1 из 32 событий p4; ни одно предсказанное событие не оказалось полностью скрытым. Частично скрытые события остались в оценке. На разработческом видео максимально мягкая оценка уникальных видимых пар дала 58.1% / 47.4%.

Допуски задержки 0.25, 0.5 и 1 секунды не добавили совпавших событий при temporal IoU ≥0.5. Общий фиксированный сдвиг покадровых предсказаний также не улучшил общую precision: после исключения перекрытий максимум на обоих контролях получен без сдвига. Это не исключает отдельных запаздывающих контактов, но общая постоянная задержка не объясняет результат.

## Почему исходная оценка низкая

**1. Правильные короткие фрагменты контакта не засчитывались целыми событиями.** На p3 есть 9, на p4 — 12 предсказаний с правильной конечностью и зацепкой, положительным пересечением во времени, но temporal IoU <0.5. Во всех 21 случае предсказание короче половины эталонного события. Один сдвиг короткого интервала не восстановит его длительность.

Пример p4, левая рука, зацепка 4: эталон **5.00–10.12 с**, предсказание **5.92–7.52 с**. Факт использования найден правильно, но восстановлены лишь 1.60 из 5.12 секунды. Поэтому прежний критерий его отклонял.

**2. Есть пространственные ошибки, которые допуск времени не исправляет.** В p3 10 из 27, в p4 15 из 36 предсказанных событий привязаны к автоматическим зацепкам без соответствия эталонной трассе. У всех этих находок максимальный box IoU с любым эталонным прямоугольником <0.3: они не потерялись из-за взаимно однозначного сопоставления ID. На p3 дополнительно есть одна неверная пара «конечность–зацепка». Отсутствие пиксельного эталона не позволяет полностью разделить ошибку позы, маски и выбора соседней зацепки.

**3. Фильтр уверенности теряет даже видимые руки.** В p3 из 219 видимых эталонных моментов контакта рук 183 (83.6%) отвергнуты из-за низкой visibility/presence; в p4 — 428 из 680 (62.9%). Это не означает, что отвергнутые координаты правильные, но показывает конкретный участок для следующего эксперимента. Неуверенность MediaPipe и перекрытие, размеченное тренером, не эквивалентны.

По разметке скрыты 62.9% времени контактов рук p3 и 34.4% p4. Исключение этих участков увеличило покадровый recall рук с 5.2% до 14.2% и с 19.8% до 30.0% соответственно. Остальные пропуски перекрытиями не объясняются.

## Вывод для следующего PoC

Если продукту нужен именно **факт видимого контакта**, следует заранее выбрать эту единицу оценки и отдельно фиксировать допустимую задержку. Значение «70%» нужно разделять на precision и recall: 80% верных ответов при обнаружении только 30% контактов — ограниченный частичный результат.

Разумный следующий эксперимент: на разработческом видео проверить фильтр уверенности кистей и устойчивость привязки к зацепке во времени; затем заморозить настройки и проверить на новых контрольных видео. Автоматический выбор трассы также требует отдельной проверки: подставлять эталонную трассу в обычный прогон нельзя. Для траекторий тела по-прежнему нужна независимая разметка координат суставов.

Исходный отрицательный вывод остаётся верным для прежнего строгого критерия. Более мягкая постановка лучше соответствует обнаружению факта контакта, но текущие результаты не подтверждают 70% для всего конвейера на обоих контролях.
