# Beta Climb - фоновый разбор видео

**Пустовой Георгий Юрьевич, Родманич Василий Александрович, Непорожнев Всеволод Васильевич**

## Сценарий

Пользователь загружает видео попытки. Разбор занимает около минуты (модели зрения и llm), поэтому API только сохраняет ролик и ставит таску, а пользователь позже открывает готовый разбор в истории. 

Задание отслеживается по `tasks.id`, попытки - по `tries` и `lease_token`.

Очередь - таблица tasks в PostgreSQL

Разбор состоит из 8 этапов, каждый - своя периодическая задача. Раз в секунду она берёт строку своего этапа, когда готовы этапы-входы.

Статусы таски: `pending` → `running` → `succeeded` / `failed` / `cancelled`.
Статусы видео: `processing` → `ready`  / `rejected` / `failed` - их пользователь видит в истории попыток.

## Как работает очередь

1. **Захват** - короткая транзакция с `FOR UPDATE SKIP LOCKED`: `status = running`, `tries + 1`, новый `lease_token`, `lease_until = now() + 90 с`.
2. **Работа** идёт вне транзакции, аренда продлевается каждые 30 с.
3. **Сохранение** - `UPDATE ... WHERE id = ? AND lease_token = ? AND status = 'running' AND lease_until > now()`. Если строка не обновилась, результат отбрасывается, а загруженные файлы удаляются из S3.

## Проверки сбоев

Обе проверки - интеграционный тест `test_lease_expiration_fences_old_owner` на PostgreSQL:

| | Ожидали | Получили |
|---|---|---|
| **1. Воркер остановился после захвата** | После истечения аренды то же задание выдаётся снова, без новой постановки | Второй захват вернул тот же `tasks.id`, `tries = 2`, новый `lease_token`; задание завершено |
| **2. Старый воркер пытается сохранить результат** | Запись отклоняется, результат нового владельца не меняется | `finish` и `heartbeat` старого владельца вернули `False`; в `videos.result_data` остался результат второго воркера; повторный `finish` тоже `False` |

Дополнительно: при штатной остановке (SIGTERM) воркер сам возвращает задание в `pending` и не тратит попытку.

## Согласованность данных

API вставляет строку `videos` и первое задание `prepare_video` в одной транзакции: при откате не остаётся ни видео, ни задания, а уже загруженный в S3 файл удаляется. Остальные 7 заданий создаются в той же транзакции, что и завершение `prepare_video`.

Файлы в S3 пишутся до фиксации в базе, по ключу с `lease_token` попытки. Поэтому повторная попытка не перезаписывает чужие файлы, а файлы отклонённой попытки удаляются.
