# Beta Climb

Фронтенд-шаблон AI-разбора одной попытки на скалодроме.

Пользователь снимает прохождение, получает 1–3 замечания, привязанных к секундам видео, и пробует то же движение ещё раз. Бэкенд, PostgreSQL и S3 здесь не реализованы. Отдельный исследовательский Python-конвейер находится в [ratpoc](ratpoc/README.md) и пока не подключён к интерфейсу.

В [отчёте RatPoC](ratpoc/REPORT.md) сохранены результаты проверки на открытых видео: лимит времени обработки выполнен на тестовом оборудовании, качество контактов пока не достигло выбранных порогов. Код, инструкции запуска, источники данных и результаты находятся в папке `ratpoc/`.

## Запуск

```bash
npm install
npm run dev
```

Приложение откроется на `http://localhost:5173`. Данные профиля и попыток лежат в `localStorage` браузера. Это хранилище шаблона, не база.

## Что делает первая версия

1. Профиль: ник, рост, вес, опыт, дисциплина, потолок категории, пол, согласие.
2. Условия съёмки: один человек, неподвижная камера, вся секция стены, различимые цвета, чёткий кадр.
3. Попытка: выбор видео остаётся на устройстве. Файл никуда не уходит.
4. Статус разбора: зацепки и трасса → положение тела и контакты → рекомендации.
5. Отказ, если кадр не подходит. Система не придумывает разбор.
6. Результат: схема попытки, главное действие на следующую попытку, ещё 1–2 наблюдения, каждое со временем.
7. Повтор той же трассы и сравнение одного движения: было / стало.
8. История по дням и сетка пролазов.

Вне первой версии: замена тренера, идеальная бета, сила и форма, несколько людей в кадре, оценка «техники» одним баллом.

## Слои

```text
src/pages          экраны
src/features       сценарии: профиль, плеер разбора
src/entities       подписи, группировка попыток
src/shared/ui      кнопки, поля, навигация
src/shared/api     контракт ClimbApi
```

Экраны не знают, откуда берутся данные. Они вызывают `useSession()`. Сессия ходит только в `climbApi`.

Сейчас `climbApi` — это `mockClient`: память и `localStorage`, таймеры вместо очереди. Чтобы подключить Java API, нужно реализовать тот же интерфейс `ClimbApi` и подставить его в `src/shared/api/climbApi.ts`. Пути будущего API собраны в `endpoints.ts`:

- `GET/PUT /api/profile`
- `GET/POST /api/attempts`
- `GET /api/attempts/:id`

Дальше по системе, уже за пределами этого репозитория: Java API, PostgreSQL для попыток и рекомендаций, S3 для видео, очередь и Python-воркер с детекцией зацепок, позой и правилами.

## Метрики, под которые собирается продукт

North Star — завершённый цикл: попытка → применимая рекомендация → повтор → наблюдаемое изменение целевого движения.

| Метрика | Что считается |
| --- | --- |
| Hold detection mAP / recall | Насколько верно найдены зацепки |
| Contact F1 | Верно ли найден контакт левой/правой руки и ноги |
| Route identification accuracy | Доля видео с правильно определённой трассой |
| Movement sequence accuracy | Совпадение последовательности движений с разметкой |
| Expert agreement | Доля рекомендаций, которые эксперт считает применимыми |
| Analysis completion | Доля видео, дошедших до результата или честного отказа |
| Second attempt rate | Доля разборов, после которых снята следующая попытка |
| Improvement rate | Доля повторов, где целевое движение изменилось |
